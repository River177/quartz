它的方法核心可以概括成一句话：

**先把预训练任务和下游任务都统一改写成“子图相似度学习”，再用一个很轻量的、任务特定的 prompt 向量去“提示”ReadOut 如何聚合子图表示，从而在冻结预训练 GNN 的前提下，把预训练知识高效迁移到节点分类和图分类。**

这篇论文主要想解决传统“pre-train, fine-tune”的一个老问题：**预训练目标和下游目标不一致**。比如预训练做的是 link prediction，本质在学“两个节点/两个局部结构是否相似”；但下游可能做 node classification 或 graph classification，本质变成“这个节点/图属于哪一类”。GraphPrompt 的思路不是简单换个分类头去 fine-tune，而是先在任务形式上做统一：让预训练和下游都落到同一个模板里。作者把这个统一模板定义为 **subgraph similarity learning**。

论文的整体方法可以分成两大部分：  
第一部分是 **unification framework**，也就是“怎么把不同任务统一起来”；  
第二部分是 **task-specific prompting**，也就是“统一之后，怎么再区分不同下游任务的个性”。这两部分加起来，就是完整的 GraphPrompt。

先说第一部分，**统一框架**。作者观察到，在图学习里，**subgraph** 是一个很自然的统一载体。对节点任务来说，一个节点本身的信息不应只看单点，而应看它周围的局部上下文，因此作者用节点的 **contextual subgraph** 表示这个节点；对图任务来说，一个图本身就可以看成它自己的最大子图。于是，无论样本是“节点”还是“图”，都可以统一写成“一个实例 $x$ 对应一个子图 $S_x$”。节点的子图通常定义为 $\delta$\-hop 邻域内的节点和边，图的子图则就是图本身。



在这个统一表示下，作者把三类任务都写成**相似度问题**：

1.  **预训练的 link prediction**：  
    给一个三元组 $(v,a,b)$，其中 $a$ 是 $v$ 的正样本邻居，$b$ 是不相连的负样本，要求
    
    $$
    \text{sim}(s_v,s_a) > \text{sim}(s_v,s_b)
    $$
    
    也就是：和我有边的节点，它的上下文子图应该和我更相似。
    
    
    
2.  **下游的 node classification**：  
    对每个类别 $c$，用该类的 $k$\-shot 标注节点的子图表示求均值，得到一个 **node class prototypical subgraph**：
    
    $$
    \tilde{s}_c=\frac{1}{k}\sum_{\ell_i=c} s_{v_i}
    $$
    
    然后对一个待预测节点 $v_j$，看它的子图表示 $s_{v_j}$ 和哪个类别原型最相似：
    
    $$
    \ell_j = \arg\max_{c\in C}\text{sim}(s_{v_j},\tilde{s}_c)
    $$
    
    这就把节点分类变成了“节点子图和类别原型子图的相似度匹配”。
    
    
    
3.  **下游的 graph classification**：  
    做法完全平行。对每个图类别 $c$，用该类的 $k$\-shot 标注图表示求均值，得到 **graph class prototypical subgraph**：
    
    $$
    \tilde{s}_c=\frac{1}{k}\sum_{L_i=c} s_{G_i}
    $$
    
    然后把待测图 $G_j$ 分到与其表示 $s_{G_j}$ 最相似的类别原型。
    
    
    

你可以看到，这样统一之后，预训练和下游任务虽然表面不同，但底层都变成了：

**先得到一个实例对应的子图表示，再做相似度比较。**  
这就是论文最核心的统一思想。

接下来是一个关键问题：**子图表示 $s_x$ 怎么得到？**  
论文先用 GNN 做正常的 message passing，得到每个节点的 embedding $h_v$。然后对一个子图 $S_x$，通过一个 ReadOut 操作，把其中所有节点表示聚合成一个子图向量：

$$
s_x = \text{ReadOut}(\{h_v: v\in V(S_x)\})
$$

作者在实现里用的是很简单的 **sum pooling**。也就是说，GraphPrompt 不是重新设计一个复杂的图编码器，而是在“GNN 编码节点后，怎么聚合成子图表示”这一层做文章。



然后进入第二部分，也就是这篇论文最有特色的地方：**prompting for downstream tasks**。  
作者认为，即便预训练和下游都统一成了“子图相似度学习”，不同下游任务之间仍然有区别。比如：

-   节点分类更关心哪些特征对目标节点表征重要；
    
-   图分类更关心哪些特征对整个图类别更相关。
    

所以，不能所有任务都用同一个固定 ReadOut。于是作者提出：**让 prompt 直接作用在 ReadOut 上。** 换句话说，GraphPrompt 里的 prompt 不是像 GPPT 那样去造 task token / structure token，也不是像 later work 那样构造 prompt graph，而是一个**任务特定的可学习向量 $p_t$**，用来对节点表示做逐维重加权，再送进 ReadOut。

具体公式是：

$$
s_{t,x} = \text{ReadOut}(\{p_t \odot h_v : v\in V(S_x)\})
$$

其中：

-   $t$ 表示某个下游任务；
    
-   $p_t$ 是这个任务的 prompt 向量；
    
-   $\odot$ 是逐元素乘法。
    

这个式子的含义很直白：  
**先用 prompt 向量对每个节点 embedding 的各个维度做 reweighting，再把这些被“提示过”的节点表示聚合成该任务下的子图表示。**

所以 prompt 的作用，不是改图结构，也不是替代分类头，而是告诉模型：  
“在这个具体任务里，子图表示的哪些维度更重要，你应该更看重它们。”



论文还提到一种替代设计：可以用一个 prompt 矩阵 $P_t$，做线性变换

$$
s_{t,x}=\text{ReadOut}(\{P_t h_v\})
$$

但作者最后没有选它，而是选了 prompt 向量。原因是这篇论文主要面向 **few-shot** 场景，标注很少，参数太多容易过拟合；向量 prompt 参数量更小，更稳。实验中的消融也说明，线性矩阵 prompt 往往不如向量 prompt。

有了 prompt 之后，node classification 和 graph classification 的原型表示，也不再是普通子图表示，而是**prompt-assisted、task-specific 的子图表示**。于是类别原型变成了：

-   节点任务：用 prompt 处理后的 labeled node subgraphs 求均值；
    
-   图任务：用 prompt 处理后的 labeled graphs 求均值。
    
    
    

再往后就是两个训练阶段。

第一阶段是 **pre-training**。  
作者在 label-free graph 上做 link prediction 预训练。具体做法是：对每个节点 $v$，随机采一个正邻居 $a$ 和一个不相连的负节点 $b$，构造 triplet $(v,a,b)$，然后最小化一个对比式损失：

$$
L_{pre}(\Theta)= - \sum_{(v,a,b)\in T_{pre}} \ln \frac{\exp(\text{sim}(s_v,s_a)/\tau)} {\sum_{u\in\{a,b\}} \exp(\text{sim}(s_v,s_u)/\tau)}
$$

这里 $\Theta$ 是 GNN 参数，$\tau$ 是 temperature。目标就是让正样本子图更相似、负样本更不相似。训练完成后得到预训练参数 $\Theta_0$。

第二阶段是 **prompt tuning**。  
这一阶段，作者**冻结预训练 GNN 参数 $\Theta_0$**，不做 fine-tuning，只优化 prompt 向量 $p_t$。对一个任务 $t$，给定少量标注样本 $T_t=\{(x_i,y_i)\}$，他们定义了 prompt tuning loss：

$$
L_{prompt}(p_t)= -\sum_{(x_i,y_i)\in T_t} \ln \frac{\exp(\text{sim}(s_{t,x_i},\tilde{s}_{t,y_i})/\tau)} {\sum_{c\in Y}\exp(\text{sim}(s_{t,x_i},\tilde{s}_{t,c})/\tau)}
$$

这里：

-   $s_{t,x_i}$ 是实例 $x_i$ 在任务 $t$ 下、经过 prompt 引导得到的子图表示；
    
-   $\tilde{s}_{t,c}$ 是类别 $c$ 的 prompt 引导原型表示。
    

这个损失本质上还是一个“正确类别原型相似度要高于其他类别原型”的 softmax 对比损失。也就是说，下游阶段并没有换成普通 classifier，而是继续沿用统一框架里的“子图相似度分类”思路。



如果把整套算法流程按顺序写出来，大概就是这样：

1.  在无标注图上，用 link prediction triplets 预训练 GNN，得到 $\Theta_0$。
    
2.  对下游任务 $t$（节点分类或图分类），初始化一个 prompt 向量 $p_t$。
    
3.  用冻结的预训练 GNN 提取所有图中的节点表示 $h_v$。
    
4.  对每个样本对应的子图 $S_x$，用 $p_t\odot h_v$ 做 prompt-assisted ReadOut，得到 $s_{t,x}$。
    
5.  用少量标注样本按类求均值，构造类别原型子图表示 $\tilde{s}_{t,c}$。
    
6.  用原型相似度损失 $L_{prompt}$ 更新 prompt 向量 $p_t$，而不是更新整个 GNN。
    
7.  测试时，对新节点/图计算其 prompt-assisted 子图表示，与各类原型求相似度，取最大者为预测类别。
    

这篇方法和 [[GNN/GPPT/方法介绍|GPPT]] 的差别也很值得注意。  
GPPT 是把节点分类改写成“类别 token 和节点 structure token 是否连边”，所以它本质更偏向 **node classification 专用**；而这篇 GraphPrompt 更抽象，它不再造 token pair，而是把问题提升到“**统一的子图相似度模板**”，因此同一个预训练模型既能做 node classification，也能做 graph classification，只需要换对应任务的 prompt 向量即可。论文里在 PROTEINS 和 ENZYMES 上甚至强调：**同一个预训练模型可同时服务这两类下游任务**。

另外，这篇方法的 prompt 也非常轻量。论文参数效率分析里，GraphPrompt 在下游 node classification 中只需要更新一个极小的 prompt 向量，参数量明显低于 end-to-end 的 GIN，也低于 GPPT；如果额外去 fine-tune 预训练权重，参数会大幅增加。作者把这点作为它适合 few-shot 的重要原因之一。

所以一句话总结这篇论文的方法：

**GraphPrompt 不是通过换分类头去适应下游，而是先用“子图相似度”把预训练和下游统一起来，再用一个任务特定的 prompt 向量去提示 ReadOut 应该强调哪些维度，从而在冻结预训练 GNN 的情况下，用很少标注完成节点分类和图分类。**
