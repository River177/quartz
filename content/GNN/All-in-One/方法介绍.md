这篇论文的方法可以概括成一句话：

**把不同层级的图任务先统一改写成“图级任务”，再往输入图里插入一个可学习的“prompt graph”，并用元学习学到一个适合多任务迁移的 prompt 初始化；预训练好的 GNN 主干保持冻结，只调 prompt 和很轻量的 task head。**



先说它要解决的问题。作者认为，传统图学习里“预训练 + 微调”之所以常常不够好，是因为**预训练任务和下游任务之间有很大鸿沟**：图任务既有节点级、边级、图级，差异很大，直接微调很容易出现负迁移。于是论文借鉴 NLP prompt 的思路，不再主要去改模型参数，而是**改输入图**，让下游任务更像预训练时见过的任务。整套框架的三根主线就是：**任务重构、prompt graph 设计、元学习**。



第一步是**任务重构（reformulate downstream tasks）**。作者先分析图任务空间，认为图级任务比节点级、边级更一般，和图预训练目标的重叠子空间更大，所以把各种下游任务尽量改写成图级任务。具体做法是构造 **induced graph**：  
对节点分类，取目标节点的 $\tau$\-ego network，也就是它在 $\tau$ 距离内的局部子图，把这个子图当作一个图样本，图标签就等于该目标节点的标签；  
对边分类，取一对节点及其 $\tau$ 距离邻域构成子图，如果这对节点有边就是正样本，没有边就是负样本，再把这条边的标签赋给子图。  
这样，原本的节点任务和边任务，都被统一成了“输入一个图，输出一个图标签”的图分类问题。这个改写是整篇方法的关键，因为后面的 prompt 和预训练都是围绕图级表示来做的。图 4 就是在说明这件事。



第二步是**prompt graph 设计**。作者不是像 NLP 那样只加一串 token，而是定义了一个真正的图提示 $G_p=(P,S)$。其中 $P$ 是一组 prompt token，每个 token 都是一个和节点特征同维度的可学习向量；$S$ 则表示这些 token 之间的连接关系，也就是 prompt graph 的内部结构。作者特别强调，图 prompt 至少要有三部分：  
**prompt token**：承载提示信息的向量；  
**token structure**：这些 token 之间怎么连；  
**inserting pattern**：prompt 怎么插入原图。  
这其实就是把 NLP prompt 的“内容 + 顺序 + 插入位置”，系统地翻译到了图场景里。



其中，**token structure** 设计了三种方式：  
一是直接学习 prompt token 之间的可训练连接参数 $a_{ij}$；  
二是用 token 两两点积，再经过 sigmoid 和阈值裁剪，自动决定哪些 token 之间连边；  
三是最简单的版本，token 彼此独立，不连边，即 $S=\varnothing$。  
这一步的含义是：prompt 本身不只是若干个孤立向量，而可以带有内部关系，从而更像一个“小图”，更适合去操纵原始图结构/特征空间。



接着是**inserting pattern**。作者不是把 prompt 粗暴地加到所有节点上，而是为每个原图节点 $x_i$ 和每个 prompt token $p_k$ 计算一个权重 $w_{ik}$，这个权重由二者点积经过 sigmoid 得到，再用阈值筛掉弱连接。于是新节点特征变成：

$$
\hat{x}_i = x_i + \sum_k w_{ik} p_k
$$

也就是说，不同节点会“接收”不同程度的 prompt 信息。论文还给了一个更简单的特例：直接把所有 prompt token 的和加到每个节点上。你可以把这一步理解成：**prompt graph 在有选择地改写输入图的节点表示，从而让这个图更匹配预训练目标。**



第三步是**多任务元学习（meta-learning）**。作者不是为每个任务单独学一个 prompt，而是把图分类、节点分类、边分类统一放进一个元学习框架里。每个任务 $\tau_i$ 都有 support set 和 query set；节点/边任务先经过前面说的 induced graph 转成图样本后再进入这一过程。参数上，$\theta$ 表示 prompt 参数，$\pi^*$ 表示冻结的预训练 GNN 主干，$\phi$ 表示下游 tasker（也就是任务头）。  
训练时分成两层：  
内层更新：在 support set 上，对每个具体任务分别更新 $\theta,\phi$；  
外层更新：在 query set 上，看这些更新后的参数表现如何，再反向优化“初始的” $\theta,\phi$。  
作者这里用的是类似 MAML 的思路，甚至写出了二阶梯度形式。直观地说，就是让 prompt 学到一种“好的初始化”，使它遇到不同任务时，都能用很少步数快速适应。算法 1 展示了完整流程：一个 multi-task episode 里同时包含 graph/node/edge 三类任务批次，然后做 inner adaptation 和 outer meta update。



整套方法的最终流程可以理解为：  
**先用 GraphCL / SimGRACE 之类图级预训练方法训好一个 backbone → 冻结 backbone → 把节点/边/图任务都整理成图级样本 → 往图里插入 prompt graph → 只训练 prompt 和轻量 task head → 再通过多任务元学习，让这个 prompt 对不同任务都更稳。** 论文实验里默认就采用了图级预训练策略，如 GraphCL 和 SimGRACE，因为作者认为它们和图级 prompt 框架更匹配。

这篇方法相对已有 GPPT 的改进点也很明确。GPPT 本质上更像“节点分类 + 边预测预训练”的特化方案，而这篇论文的方法更通用：  
它支持**节点级、边级、图级**多种下游任务；  
兼容**GraphCL、SimGRACE** 这类更强的图级预训练；  
prompt 不是孤立 label token，而是有**多 token、内部结构、插入模式**的 prompt graph；  
再加上元学习，适应新任务时更稳定。论文还指出，GPPT 实际上可以被看成他们框架的一个特例。



最后，作者还解释了为什么这套方法有效：  
一是**更灵活**，因为 prompt 的本质是对输入图做“可学习的图变换”，从单 token 扩展到有结构的 prompt graph 后，能更细致地逼近目标变换；  
二是**更高效**，因为只调 prompt，不动 backbone，参数复杂度主要是 $O(nd)$，而不是整模型级别；  
三是**更兼容**，因为方法重心放在“改输入以匹配预训练任务”，所以对具体下游 task head 的依赖比传统 fine-tuning 更小，甚至论文还设计了一个**不调 task head** 的 variant：对 $k$ 类分类任务构造 $k$ 个子 prompt，分别生成 $k$ 个图视图，谁和输入 induced graph 最接近就判成哪一类。
