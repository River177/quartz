这篇 **RELIEF** 的方法，核心不是“给所有节点都加 prompt”，而是：

**把“该给哪些节点加 prompt、每个 prompt 该长什么样”建模成一个序列决策问题，用强化学习一步一步往图里加少量、轻量的 feature prompts，从而在冻结预训练 GNN 的前提下，提升下游 few-shot 任务表现。**

它和已有 feature prompt 方法的分歧点很明确。像 GPF、GPF-plus、SUPT 这类方法虽然不依赖特定预训练策略，通用性很好，但通常默认“给很多甚至所有节点都加 feature prompt”。RELIEF 认为这未必合理：如果 prompt 太多、幅度太大，会扰乱原始输入特征空间，让预训练 GNN 看到一个“陌生图”，反而损害迁移效果。作者受 NLP 里“更强的预训练模型往往只需要更少 conditioning signal”这个观察启发，主张只加**必要且轻量**的 prompt。



所以这篇论文的方法可以分成四层来理解：

1.  把 feature prompting 重写成一个 **MDP / 序列决策问题**
    
2.  用一个 **混合动作空间 RL 策略网络** 决定“选哪个节点、加什么 prompt”
    
3.  用 **交替训练** 协调 RL 策略和下游 projection head
    
4.  用 **policy generalization** 和两个指标去保证方法稳、并解释它为什么有效。

先说基础设定。  
给定一个预训练好的 GNN 编码器 $f_\theta$ 和一个下游 projection head $g_\phi$。在普通 fine-tuning 里，$\theta,\phi$ 都要更新；在普通 graph feature prompt tuning 里，$f_\theta$ 冻结，只学习 prompting function $u_\psi$ 去把图 $G$ 变成 prompted graph $u_\psi(G)$，同时通常还要调 $g_\phi$。如果是 feature prompt，它具体表现为给每个节点特征 $x_i$ 加上一个 learnable vector $p_i$，得到：

$$
x_i^* = x_i + p_i
$$

于是整个图的 prompted feature matrix 就是 $X^*=X+P$。RELIEF 认可这种“feature prompt 与预训练策略解耦”的路线，但不接受“默认所有节点都要 prompt”这个假设。



真正的创新从这里开始：RELIEF 把 prompt 插入过程视为一个 **Markov Decision Process**。

---

### 1\. MDP formulation：把加 prompt 过程变成逐步决策

论文把“往图里加 prompt”做成一个多步过程，而不是一次性直接输出整个 prompt 矩阵。  
在第 $t$ 步，agent 要做一个**混合动作**：

-   **离散动作 $a_t$**：选哪个节点 $v_a$ 来 prompt
    
-   **连续动作 $z_t$**：给这个节点加什么 prompt 向量。
    
    
    

所以一个动作可以记成：

$$
(a_t,z_t)=p_t^{a,z}
$$

这里 $z_t\in \mathbb R^{1\times D}$，其中 $D$ 是节点特征维度。  
如果把所有节点当前累计的 prompts 记成矩阵 $P_t$，初始时 $P_0$ 是全零矩阵，表示还没加任何 prompt。每走一步，只更新选中节点对应的那一行：

$$
P_t = P_{t-1} + p_t^{a,z}
$$

于是 prompted features 变成：

$$
X_t^* = X + P_t
$$

这说明 RELIEF 不是一次性学习一个全局 prompt，而是**一步一步累积 prompt**。



#### 状态怎么定义

状态 $s_t$ 不是原始图结构，而是**当前 prompted graph 经过冻结预训练 GNN 后得到的节点表示**：

$$
s_t = f_\theta(G_{t-1}^*) = f_\theta(X_{t-1}^*, A)
$$

也就是当前 prompt 加到什么程度，GNN 看完后每个节点的表示长什么样，agent 就在这个 latent state 上继续决策下一步。



因为不同图节点数不同，不方便 batch 训练，论文设了一个最大节点数 $N$，不足的部分用零向量 padding，统一成固定尺寸状态张量。



#### 奖励怎么定义

最关键的是 reward。  
作者没有直接用 AUC/F1 这类整数据集指标，因为他们需要一个**针对单个图、单一步动作**的即时奖励。于是定义成**loss decrease**：

$$
r_t = L_{t-1}-L_t
$$

也就是：

-   如果这一步加 prompt 让当前样本 loss 下降，reward 为正
    
-   如果反而让 loss 变大，reward 为负。
    
    
    

这个设计非常贴切：它直接鼓励 agent 去找“哪一步 prompt 会让当前下游损失继续下降”。从而累计 reward 就等价于累计 performance gain。



---

### 2\. Policy network：用混合动作 RL 来决定“加到哪、加多少”

因为动作同时包含离散选择和连续向量，普通 PPO 或 DQN 都不合适。RELIEF 采用的是 **H-PPO**，也就是适用于 hybrid action space 的 PPO 变体。它有三个部分：

-   一个 **discrete actor**
    
-   一个 **continuous actor**
    
-   一个 **critic**。
    
    
    

它们共享前面的状态编码器，而这个状态编码器本质上就是**冻结的预训练 GNN $f_\theta$**。然后后面接不同的 MLP 来分别输出离散动作、连续动作和值函数。



#### Discrete actor：选节点

给定当前状态 $s$，离散 actor 输出每个节点被选中的概率：

$$
p(a|s) \leftarrow \text{Softmax}(\text{MLP}_a(f_\theta(G^*)))
$$

也就是 agent 先决定“下一步 prompt 加到哪个节点上”。  
这一步非常关键，因为论文后面的消融显示：**离散 actor 比连续 actor 还更关键**。原因很直观——如果节点选错了，即使 prompt 值选得再精细，也可能把错误信号扩散到图里。



#### Continuous actor：选 prompt 内容

选定节点 $a$ 后，continuous actor 再输出该节点的 prompt 向量均值 $\mu(s,a)$，然后从高斯分布里采样得到一个连续向量 $z$ 作为本步 prompt：

$$
\mu(s,a)\leftarrow \text{MLP}_z(f_\theta(G^*))[a]
$$

采样后还会把每个维度 clamp 到 $[ -z_{\max}, z_{\max} ]$，其中 $z_{\max}$ 是一个控制单步 prompt 幅度的超参数。这个设计也是为了保证 prompt 保持“lightweight”。太大就容易破坏输入分布，太小又接近没加。

#### Critic：估计状态价值

critic 负责估计 $V(s)$。由于状态是 $N\times d$ 的节点表示矩阵，而 value 是图级标量，论文先把节点表示 flatten，再过一个 MLP 输出实数值。这样 critic 就能告诉 actor：当前 prompt 之后的状态整体好不好。

### 3\. RELIEF 的整体训练：策略网络和投影头交替训练

这篇论文还有一个非常重要的点：**RL policy 和 projection head 不是一起端到端同时乱调，而是交替训练**。这也是 Figure 2 的核心。

#### 3.1 先训练 policy network

先固定：

-   预训练 GNN $f_\theta$ 冻结
    
-   当前 projection head $g_\phi$ 暂时视为固定
    

然后 agent 在每个图上连续执行 $n$ 步 prompt addition，其中 $n$ 等于节点数，理论上让每个节点都有机会被选到。每一步收集 transition：

$$
(s,a,z,r,s')
$$

所有这些 transition 进入 buffer，随后用 PPO surrogate objective 更新两个 actor，用 MSE 更新 critic。



这一步的本质是：  
**先学一个尽量好的“加 prompt 策略”。**

#### 3.2 再训练 projection head

有了当前策略后，再用它给图连续加 $n$ 步 prompt，得到最终 prompted graph $G^*$。  
这时不再随机采样连续动作，而是把 continuous policy 改成 deterministic，保证同样的 state 和节点选择对应同样的 prompt 值，从而得到稳定的 prompted representation。然后只更新 projection head：

$$
\min_\phi \frac{1}{m}\sum_{i=1}^m L(g_\phi(f_\theta(G_i^*)), y_i)
$$

这里 $q$ 表示每个 epoch 内 projection head 更新的次数。论文明确说，一个 epoch 就是：

-   先训练 policy network 一次
    
-   再训练 projection head $q$ 次。
    

你可以把这个过程理解成：

-   RL 负责学“怎么改输入”
    
-   projection head 负责学“怎么读这种改造后的表示”  
    二者轮流协调，而不是一次全交给 RL 或一次全交给监督学习。
    
    
    

---

### 4\. Policy generalization：为了防止 few-shot 下 RL 过拟合

few-shot prompt tuning 最大的问题之一是：RL 很容易只记住训练图的局部模式，泛化到新图就差。为了解决这个问题，RELIEF 引入了 **LEEP** 这一 policy generalization 技术。



它的思路是 ensemble：

-   学 $l$ 个 discrete sub-policies $\pi_{d,1},\dots,\pi_{d,l}$
    
-   学 $l$ 个 continuous sub-policies $\pi_{c,1},\dots,\pi_{c,l}$
    
-   每个 sub-policy 都在 bootstrap 采样出来的一部分训练图上训练
    
-   但训练时还加一个 KL 正则，让每个 sub-policy 不要偏离 joint policy 太远。
    
    
    

#### 离散 joint policy

离散 joint policy 取各个 sub-policy 对每个动作的最大概率，再归一化：

$$
\pi_{d,J}(a|s)= \frac{\max_i \pi_{d,i}(a|s)} {\sum_{a'} \max_i \pi_{d,i}(a'|s)}
$$

这意味着联合策略更偏向那些被多个 sub-policies 都认为靠谱的节点选择。



#### 连续 joint policy

连续 joint policy 则更简单，用均值平均：

$$
\pi_{c,J}(z|s,a)=\frac{1}{l}\sum_{i=1}^l \pi_{c,i}(z|s,a)
$$

也就是不同连续子策略对 prompt content 的建议取平均。



最终测试时，不是用单个 actor，而是用这两个 joint policies 去一步一步往图里加 prompt。  
这一步的重要性也在实验里被强调：把 $l$ 设成 1，相当于去掉 policy generalization，性能会明显下降。

### 5\. 方法的核心目标：necessary and lightweight prompts

论文不只是提出方法，还专门设计了两个指标，来量化“prompt 到底有多少、多轻”。

#### Prompt Coverage Ratio (PCR)

衡量最终有多少比例的节点被 prompt 过：

$$
PCR(G)=\frac{1}{n}\sum_{i=1}^n \mathbf 1[p_i\neq 0]
$$

也就是有 prompt 的节点数 / 总节点数。



#### Average Prompt Magnitude (APM)

衡量有效 prompt 的平均幅度：

$$
APM(G)=\frac{1}{n}\sum_{i=1}^n \frac{1}{D}\mathbf 1[p_i\neq 0]\|p_i\|_1
$$

也就是只对非零 prompt 计算平均 L1 强度。



这两个指标合起来衡量 prompt 对原始输入空间的扰动程度。论文实验里还把二者相乘当 overall impact，结果表明 RELIEF 的 PCR、APM 都低于其他 feature prompt 方法，但性能反而更高。这正是它“少而精”的证据。

### 6\. 这篇方法和现有方法的关系

RELIEF 对已有方法的定位很清楚。

它不属于：

-   那种依赖特定预训练任务的 prompt 方法，比如 GPPT、GraphPrompt、All in One  
    因为那些方法往往要显式对齐某种 pretext。
    
    
    

它属于：

-   **pre-training-agnostic feature prompt tuning** 这一类  
    也就是像 GPF/GPF-plus/SUPT 一样，通过改输入特征来适配任意预训练策略。
    
    
    

但 RELIEF 和它们的区别是：

-   不是默认所有节点都 prompt
    
-   不是一次性直接学习整张图的 prompt 矩阵
    
-   而是用 RL 逐步决定“在哪些节点、加什么 prompt”。
    
    
    

所以这篇方法的本质，可以概括成一句很直白的话：

**把 feature prompt tuning 从一个静态参数优化问题，变成一个动态的 sequential prompt placement problem。**



---

### 7\. 为什么作者认为 RELIEF 会工作

论文最后给了三点解释，我觉得也很关键。

第一，**Powerful**。  
因为 RL 擅长组合优化，而“选节点 + 配 prompt”本来就是一个离散-连续混合、组合爆炸的问题。只要 reward 合理、训练稳定，RL 就能搜到高质量 prompt 策略。



第二，**Necessary**。  
如果某一步 prompt 加在了不该加的节点上，会导致 cumulative reward 下降，critic 会把这种坏决策学进去，推动 actor 避免无效 prompt。所以最终学到的是“必要节点上的 prompt”。



第三，**Lightweight**。  
如果 prompt 幅度太大，GNN 会看到陌生表示，projection head 也难以配合，loss 反而上升，reward 变负。于是 actor 会被惩罚，逐渐学会更温和的 prompts。也就是说，“轻量”不是手工规定出来的，而是由 reward 机制逼出来的。



---

### 8\. 一句话总结

这篇论文的方法可以总结为：

**RELIEF 把图特征 prompt 的插入过程建模成一个混合动作空间的强化学习问题：离散 actor 选节点，连续 actor 生成 prompt 向量，critic 通过单步 loss 降低来评价每次 prompt addition 的好坏；再通过交替训练 projection head 与 LEEP 风格的 policy generalization，最终学到一套能在冻结预训练 GNN 上只插入必要且轻量 prompts 的策略。**
