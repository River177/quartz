它的方法核心不是“预训练一个图编码器，再到下游 fine-tune”，而是：

**直接把“few-shot 任务本身”表示成一个图，再用预训练让模型学会“看着几个示例就直接做新任务”，也就是图上的 in-context learning。**

可以把整篇方法拆成三层来理解：

1.  **先定义图上的 in-context 任务长什么样**
    
2.  **把这个任务表示成一个 prompt graph**
    
3.  **围绕 prompt graph 设计模型和预训练目标，让模型学会从示例里推断新查询的标签**

---

### 1\. 它想解决什么问题

大语言模型的 in-context learning 是：给几个输入-输出示例，不更新参数，模型就能直接做新任务。  
这篇论文想把这件事搬到图上。

但图上比文本难很多，因为图任务有：

-   节点分类
    
-   边分类
    
-   子图/图分类

而且每个输入样本都不是孤立的，它依赖**原图里的邻域上下文**。所以不能只给“样本 + 标签”，还必须把它在原图中的上下文也带进来。论文因此提出：**few-shot prompt 必须包含 source graph $G$、prompt examples $S$、以及 queries $Q$**。



---

### 2\. 统一任务形式：把不同图任务都写成“输入是一个小图”

论文先做了一步很关键的统一。

它把所有分类任务都写成：

-   输入 $x_i$ 其实是一个图/子图
    
-   输出是一个类别 $y_i$

于是：

-   **节点分类**：输入图里只有 1 个节点
    
-   **边分类**：输入图里有 2 个节点，表示一对待判断关系的节点
    
-   **更一般的子图/图分类**：输入本身就是一个更大的子图


也就是说，它先把 node / edge / graph 任务都统一到“**输入是图**”这个视角上。这样后面才能用同一种 prompt 表示。

---

### 3\. Prompt graph：这篇论文最核心的表示

论文提出的 **prompt graph**，是图上的“提示模板”。它由两部分组成：

-   **data graphs**
    
-   **task graph**

#### 3.1 Data graph：给每个样本补上上下文

无论样本来自 prompt examples 还是 query，先都要在原图 $G$ 里做一次 **contextualization**。  
做法是：围绕这个样本的输入节点集合 $V_i$，去原图里取一个 $k$\-hop 邻域，构成一个 **data graph** $G_i^D$。

这一步的直觉是：

-   节点本身的信息不够，要看邻居
    
-   边本身的信息也不够，要看两端节点周围结构
    
-   但又不能把整张大图都塞进模型，所以只取局部子图

因此，每个样本最终都会对应一个局部上下文图 $G_i^D$。论文在图 1 的 (B) 部分就是在画这件事。


#### 3.2 Task graph：把样本和标签放到同一张图里

接着，论文再构造一个 **task graph** $G^T$。  
这里会有两类节点：

-   **data node** $v_{x_i}$：每个样本一个
    
-   **label node** $v_y$：每个类别一个

然后连边规则很巧妙：

对 **prompt examples**，因为标签已知，所以把该样本节点连到所有 label nodes：

-   连到真实标签对应的边标记为 **T**
    
-   连到其他标签对应的边标记为 **F**

对 **queries**，因为标签未知，就只从所有 label nodes 指向 query data node，表示“这些标签都可能，你来判断”。论文图 1 的 (C) 就是在画这个 task graph：绿色/红色是示例上的真/假标签边，黄色是查询上的待判定连接。

#### 3.3 为什么这个表示重要

这个 prompt graph 很像语言模型里的 prompt，只不过这里不是自然语言，而是一个图结构化提示：

-   **data graph** 负责把每个样本的局部上下文编码进去
    
-   **task graph** 负责把“示例、查询、标签之间的关系”显式组织起来
    

这样模型在一次前向传播里，就能同时看到：

-   support examples 的内容
    
-   support examples 的标签
    
-   queries
    
-   所有候选标签

于是“从示例中学任务”这件事，就被变成了图上的消息传递问题。

---

### 4\. 模型结构：两段式 message passing

PRODIGY 的模型不是只跑一层 GNN，而是分两段：

-   **先在 data graph 上做消息传递**
    
-   **再在 task graph 上做消息传递**

#### 4.1 Data graph message passing：先学每个样本自己的表示

第一步，用一个 GNN 模块 $M_D$ 处理每个 data graph $G^D$，得到里面节点的 embedding：

$$
E = M_D(G^D)
$$

这一步就是普通的图编码。

然后要把整个 data graph 压成一个向量 $G_i$，作为这个样本的表示。

-   对 **节点分类**，最简单：直接取目标节点的最终表示
    
-   对 **边分类**，取两端节点表示，再拼接一个全图 max pooling，最后过一个线性层：
    

$$
G_i = W^T(E_{v_1} \| E_{v_2} \| \max(E_i)) + b
$$

这表示边分类既看 head/tail 节点本身，也看局部上下文整体。

#### 4.2 Task graph message passing：让示例、标签、查询互相通信

第二步，把上面每个样本的表示 $G_i$ 放到 task graph 里的 data nodes 上，再用另一个 GNN $M_T$ 在 **task graph** 上做消息传递：

$$
H = M_T(G^T)
$$

这里 label nodes 也有表示。它们初始可以随机初始化，或者带额外标签信息。

task graph 上的边还有两个二值特征：

-   这条边是不是来自 example 还是 query
    
-   这条 example-label 边是真标签 T 还是假标签 F

作者在这里用的是 **attention-based GNN**。直觉上，这一层的作用是：

-   让 prompt examples 通过 label nodes 把“这个任务长什么样”传出去
    
-   再让 queries 从 label nodes 和 examples 那里吸收这些信息
    
-   最后让每个 query 形成一个“已经结合上下文示例后的任务特定表示”

论文还特别指出，**label nodes 是一个 information bottleneck**。也就是说，不同示例并不是随便全连，而是通过“标签节点”这个中介共享信息。这个设计很像“类别原型 + 任务路由器”的组合。

#### 4.3 Prediction readout：最后怎么出分类结果

最后，对每个 query，不再接一个普通分类头，而是直接计算 query data node 和每个 label node 的余弦相似度：

$$
O_i = [\text{cosine\_similarity}(H_{x_i}, H_y), \forall y \in Y]
$$

这些相似度就是 logits。哪个 label node 最像这个 query，就预测成哪个类。

这点很重要：  
**它没有为每个下游任务专门训练一个新 head，而是统一成“query 表示和 label 表示做相似度匹配”。**

---

### 5\. 预训练怎么做：不是普通预训练，而是“以 in-context 的形式预训练”

这是这篇论文和普通 graph pretraining 最大的不同。

普通方法一般是：

-   预训练一个 encoder
    
-   下游再 fine-tune


而 PRODIGY 是：

-   **直接生成很多 few-shot 任务**
    
-   把这些 few-shot 任务都转成 prompt graph
    
-   训练模型学会“看着 prompt examples 直接推 query”


也就是：**预训练阶段就已经在模拟测试时的 in-context 学习形式。**

论文提出了两类预训练任务。

#### 5.1 Neighbor Matching：自监督的 in-context 预训练任务

这是论文最有代表性的设计。

它先在预训练图里随机采样 $m$ 个节点，把每个节点视为一个“类中心” $c_i$。  
然后定义每个类的局部邻域：

$$
N_i = \text{Neighbor}(c_i, G_{pretrain}, l)
$$

再从每个邻域里采样：

-   $k$ 个节点做 support examples
    
-   若干个节点做 queries

于是，一个 few-shot 任务就变成：

**判断某个 query 节点属于哪一个“局部邻域类”。**



直观地说，这个任务在逼模型学会：

-   看到几个属于某个 neighborhood 的示例
    
-   再判断一个新节点是不是也属于那个 neighborhood

如果下游是 edge classification，它还可以把节点扩展成边：对每个采样节点随机挑一条 incident edge，把任务改成“这条边属于哪个 neighborhood”。


这个任务的好处是：

-   **完全自监督**
    
-   不需要额外标签
    
-   天然可以构造成 few-shot prompt 的形式


#### 5.2 Multi-task：有监督的 few-shot 预训练任务

如果预训练图本身有节点标签或边标签 $f(x)=y$，那还可以直接构造更贴近下游的 few-shot 任务。

做法是：

-   先采样 $m$ 个类别
    
-   每个类别采样 $k$ 个 support
    
-   再采样一些 query
    
-   组成一个 few-shot 分类任务


对节点任务就是节点标签 few-shot 分类；  
对边任务就是 relation type few-shot 分类。

这类任务更像真实下游，但它依赖标签；而 Neighbor Matching 更通用、更自监督。  
所以论文最后的完整 PRODIGY 是 **PG-NM + PG-MT 的结合**。



---

### 6\. Prompt graph 预训练时还做了什么增强

论文在把 few-shot prompt 转成 prompt graph 之后，还对每个 data graph 做了图增强，借鉴了 contrastive learning 的思路。主要两种：

-   **DropNode**：随机丢节点
    
-   **MaskNode**：随机把部分节点特征置零

目的不是做对比损失本身，而是让模型学到对这些局部扰动更鲁棒的表示。

另外，附录里还加了一个 **attribute prediction loss**：  
如果某些节点特征被 mask 了，就让模型从学到的 embedding 重建原始特征。这个辅助目标对 PG-NM 提升挺明显。附录的消融里说，去掉 attribute prediction 平均会掉大约 7%。


---

### 7\. 最终训练目标

论文最后的主损失是把 Neighbor Matching 和 Multi-task 两种 prompt-graph 任务的交叉熵加起来：

$$
L = \mathbb{E}_{x_i \in Q^{NM}} CE(O^{NM}_i, y^{NM}_i) + \mathbb{E}_{x_i \in Q^{MT}} CE(O^{MT}_i, y^{MT}_i)
$$

也就是说：

-   每次先采样 few-shot 任务
    
-   构造 prompt graph
    
-   模型输出 query 对各个 label 的 logits
    
-   对 query 的真实标签做 cross-entropy

训练到最后，模型学到的不是“某个单一任务”，而是：

**如何从 prompt examples 中读取规律，并把这个规律迁移到 query 上。**

---

### 8\. 测试时怎么用

到了真正下游任务时，流程和预训练时是一致的：

1.  给一个新图 $G$
    
2.  给少量 labeled prompt examples $S$
    
3.  给若干 queries $Q$
    
4.  构造 prompt graph
    
5.  直接跑模型，输出 query 标签

**不需要再 fine-tune。**  
这就是它所谓的图上的 in-context learning。


---

### 9\. 这篇方法为什么有效

我觉得这篇方法最关键的优点有三点。

第一，它找到了图上的“prompt 等价物”。  
在语言里，prompt 是文本；在这里，prompt 是 **prompt graph**，把样本、标签、上下文、示例关系都编码进去了。


第二，它不是只学 encoder，而是**直接学“如何根据示例做任务”**。  
预训练阶段就一直在做 few-shot task over prompt graph，所以测试时不需要再改学习范式。


第三，它把支持集和查询集的交互显式建模了。  
普通 prototype 或 nearest-neighbor 方法，通常只是“先编码，再硬算相似度”；而 PRODIGY 让 support、query、labels 通过 task graph 做消息传递，这个适应过程是可学习的。


---

### 10\. 和前面几篇 graph prompt 工作的区别

如果和你前面看的几篇对比，差别很明显：

-   **GPPT**：核心是把 node classification 改写成 link prediction，更像“prompt tuning”
    
-   **GraphPrompt / All in One**：强调统一预训练任务和下游任务，或者用 prompt 引导 ReadOut / prompt graph
    
-   **PRODIGY**：更进一步，它要解决的不是“更好地 fine-tune”，而是**完全不 fine-tune 的 in-context learning**。


所以这篇论文的真正目标不是 parameter-efficient transfer，而是：

**让图模型像大语言模型那样，看到几个示例后就能直接做新图任务。**


一句话总结：

**PRODIGY 用 prompt graph 把 few-shot 图任务表示成一张“样本—标签—查询”联合图，再通过 data graph + task graph 两阶段消息传递，以及专门的 in-context 预训练任务，让模型学会不用 fine-tuning、只靠示例就在新图上做分类。**
