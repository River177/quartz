这篇论文提出的方法叫 **ProNoG：Prompt learning framework for Non-homophilic Graphs**，中文可以理解为：

> 面向非同配图的图预训练与提示学习框架。

它主要解决的问题是：很多真实图并不是纯同配图，也不是纯异配图，而是 **non-homophilic graph**，即图中同时存在同配和异配模式，并且不同图、不同节点的同配/异配程度都不一样。传统图 prompt 方法通常给所有节点用同一个 prompt，无法适应这种节点级差异。ProNoG 的核心思路是：**先选择更适合非同配图的预训练任务，再用条件网络为每个节点生成专属 prompt**。



---

## 1\. 论文的核心问题：什么是 non-homophilic graph？

传统 GNN 很多时候默认 **homophily assumption**：

> 相连节点更可能属于同一类别。

例如论文图 1(a) 中，Cora 的同配边比例较高，因此更像同配图；而 Wisconsin 的同配边比例较低，更像异配图。论文进一步指出，真实图通常不是单纯同配或异配，而是 **non-homophilic**：不同图、不同任务标签、不同节点都可能表现出不同的同配/异配特征。



论文给了两个重要定义。

图级同配率：

$$
H(G)= \frac{ |\{(u,v)\in E:y_u=y_v\}| }{ |E| }
$$

表示一张图中有多少比例的边连接的是同类节点。

节点级同配率：

$$
H(v)= \frac{ |\{u\in N(v):y_u=y_v\}| }{ |N(v)| }
$$

表示一个节点的邻居中，有多少比例和它同类。

这两个定义非常关键，因为 ProNoG 的方法就是围绕“不同节点有不同的非同配模式”展开的。



---

# 2\. 方法整体框架

ProNoG 包含两个阶段：

```
阶段一：Non-homophilic graph pre-training  
      使用更适合非同配图的预训练任务训练图编码器  
  
阶段二：Conditional prompt learning  
      冻结预训练图编码器  
      为每个节点生成 node-specific prompt  
      用少量下游标签进行 prompt tuning
```

论文图 2 展示了完整流程：左侧是图编码器预训练，中间是下游任务适配，右侧是对某个节点提取 2-hop 子图并生成专属 prompt 的细节。

# 3\. 第一部分：重新思考图预训练任务

论文不是直接提出 prompt，而是先分析：**对于非同配图，什么预训练任务更合适？**

很多已有图 prompt 方法使用 link prediction 作为预训练任务，例如 GPPT、GraphPrompt 等。

link prediction 的基本假设是：

> 如果两个节点有边，它们应该更相似；如果没有边，它们应该不相似。

这其实隐含了同配假设。

但是在非同配图中，相连节点可能本来就是不同类、不同语义的。如果仍然强行让相连节点表示更接近，就可能学到错误的表示。

---

## 3.1 对比式预训练任务形式

论文把主流对比预训练任务统一写成：

$$
T=(\{A_u:u\in V\},\{B_u:u\in V\})
$$

其中：

-   $A_u$：节点 $u$ 的正样本集合；
    
-   $B_u$：节点 $u$ 的负样本集合。
    

对应损失为：

$$
L_T = -\sum_{u\in V} \ln P(u,A_u,B_u)
$$

其中：

$$
P(u,A_u,B_u) = \frac{ \sum_{a\in A_u} sim(h_u,h_a) }{ \sum_{a\in A_u} sim(h_u,h_a) + \sum_{b\in B_u} sim(h_u,h_b) }
$$

目标是：让节点 $u$ 和正样本更相似，和负样本更不相似。

---

## 3.2 Homophily task 的定义

论文定义了 **homophily task**：

如果对于每个节点 $u$：

-   正样本 $a\in A_u$ 都是和 $u$ 相连的节点；
    
-   负样本 $b\in B_u$ 都是不和 $u$ 相连的节点；
    

那么这个预训练任务就是 homophily task。

link prediction 就属于典型的 homophily task，因为它默认“有边更相似，无边更不相似”。

---

## 3.3 为什么 homophily task 不适合非同配图？

论文进一步定义了 **homophily sample**。

对于一个三元组 $(u,a,b)$：

-   $(u,a)\in E$，即 $a$ 是 $u$ 的邻居；
    
-   $(u,b)\notin E$，即 $b$ 不是 $u$ 的邻居。
    

如果：

$$
sim(h_u,h_a)>sim(h_u,h_b)
$$

那么它是 homophily sample。

反之，如果邻居 $a$ 反而没有非邻居 $b$ 相似，那么它就是 non-homophily sample。

论文证明了两个结论：

1.  对于 homophily task，加入 homophily sample 会比加入 non-homophily sample 带来更小的损失；
    
2.  图的同配率越低，homophily sample 越少，non-homophily sample 越多。
    

所以结论是：

> 在低同配率图上，用 link prediction 这类 homophily task 预训练，会遇到更多不符合任务假设的样本，从而导致预训练效果变差。
> 
> 

---

## 3.4 ProNoG 选择什么预训练任务？

论文将预训练任务分成两类：

| 类型 | 代表方法 | 特点 |
| --- | --- | --- |
| Homophily pre-training | GPPT、GraphPrompt、HGPrompt | 依赖 link prediction，假设有边更相似 |
| Non-homophily pre-training | DGI、GraphCL、GraphACL | 正负样本不直接依赖是否连边 |

ProNoG 主张使用 **non-homophily pre-training task**。

论文实验中主要发现：GraphCL 这类 non-homophily 预训练方法在同配图和非同配图上都比较稳健。论文表 4 也比较了 link prediction、GraphACL、GraphCL，结果显示在 Wisconsin、Cornell 等低同配图上，GraphCL 这类非同配预训练任务明显更优。

# 4\. 第二部分：Non-homophilic Prompt Learning

预训练完成后，ProNoG 进入下游 prompt learning 阶段。

已有图 prompt 方法通常是：

> 给所有节点使用一个统一 prompt。

例如：

$$
\tilde{h}_v = p \odot h_v
$$

其中 $p$ 对所有节点都一样。

但 ProNoG 认为这不合理，因为不同节点的局部非同配模式不同。

例如：

-   有的节点周围大多是同类邻居；
    
-   有的节点周围大多是异类邻居；
    
-   有的节点 1-hop 邻居同配，但 2-hop 邻居异配；
    
-   有的节点同配率相同，但邻居的分布结构不同。
    

所以 ProNoG 不是学习一个全局 prompt，而是通过 **condition-net** 给每个节点生成自己的 prompt。

---

# 5\. 节点非同配模式提取：读取多跳子图

对于每个节点 $v$，ProNoG 首先提取它的 $\delta$\-hop ego-network：

$$
S_v
$$

也就是以 $v$ 为中心的 $\delta$ 跳子图。

论文实验中设置：

$$
\delta = 2
$$

因为 2-hop 可以兼顾效率和局部结构表达能力。



---

## 5.1 为什么要看 2-hop 子图？

只看节点自身 embedding $h_v$ 不够，因为它不能充分反映该节点周围的非同配模式。

ProNoG 希望 prompt 不是只由节点自身决定，而是由节点周围的局部结构决定。

例如一个节点可能有：

```
节点 A：1-hop 邻居多为同类，2-hop 邻居多为异类  
节点 B：1-hop 邻居多为异类，2-hop 邻居多为同类  
节点 C：邻居分布混杂
```

这些节点应该使用不同的 prompt。

---

## 5.2 相似度加权 readout

对于节点 $v$ 的子图 $S_v$，ProNoG 用相似度加权的方式得到子图表示 $s_v$：

$$
s_v = \frac{1}{|V(S_v)|} \sum_{u\in V(S_v)} h_u \cdot sim(h_u,h_v)
$$

其中：

-   $h_v$：中心节点 $v$ 的表示；
    
-   $h_u$：子图中节点 $u$ 的表示；
    
-   $sim(h_u,h_v)$：节点 $u$ 和中心节点 $v$ 的相似度；
    
-   $s_v$：用于描述节点 $v$ 局部非同配模式的子图表示。
    

直观理解：

> 如果某个邻居和中心节点更相似，它在子图 readout 中权重更大；如果不相似，它贡献较小。

这样可以让 $s_v$ 更好地刻画节点 $v$ 的局部同配/异配模式。

论文图 2(c) 中展示了这个过程：先取节点 $v$ 的 2-hop 子图，然后计算中心节点与子图中每个节点的相似度，再进行加权 readout，得到 $s_v$。



---

# 6\. Condition-net：为每个节点生成专属 prompt

得到 $s_v$ 后，ProNoG 使用一个条件网络生成节点级 prompt：

$$
p_{t,v} = CondNet(s_v;\phi_t)
$$

其中：

-   $t$：当前下游任务；
    
-   $v$：节点；
    
-   $s_v$：节点 $v$ 的局部非同配模式表示；
    
-   $CondNet$：条件网络；
    
-   $\phi_t$：该任务对应的 condition-net 参数；
    
-   $p_{t,v}$：为节点 $v$ 生成的专属 prompt。
    

这里的 condition-net 可以理解为一个小型 MLP。

论文中使用的是带 bottleneck 的 MLP，也就是先降维再升维，从而减少参数量，避免 few-shot 场景下过拟合。



---

## 6.1 这个设计的关键意义

ProNoG 不是直接为每个节点存一个可学习 prompt：

$$
p_v
$$

因为这样参数量会随着节点数增长，而且 few-shot 标签太少，容易过拟合。

它采用的是：

$$
p_{t,v}=CondNet(s_v;\phi_t)
$$

也就是说：

> prompt 不是节点自己的独立参数，而是由共享的 condition-net 根据节点局部模式动态生成。

这样有两个好处：

1.  **参数少**：只训练 condition-net，不为每个节点单独存参数；
    
2.  **节点自适应**：不同节点输入的 $s_v$ 不同，因此生成的 prompt 不同。
    

---

# 7\. Prompt 如何作用到节点表示上？

ProNoG 生成 prompt 后，用它调整节点表示。

论文中使用的是 element-wise product：

$$
\tilde{h}_{t,v} = p_{t,v} \odot h_v
$$

其中：

-   $h_v$：冻结的预训练图编码器输出的节点表示；
    
-   $p_{t,v}$：condition-net 生成的节点专属 prompt；
    
-   $\odot$：逐元素乘法；
    
-   $\tilde{h}_{t,v}$：适配下游任务后的节点表示。
    

这个操作类似于对 embedding 的不同维度进行重新加权：

```
某些维度对当前节点更重要 → prompt 权重大  
某些维度可能受异配噪声影响 → prompt 权重小
```

因此，ProNoG 可以根据每个节点的局部非同配模式，动态调整其表示。

---

# 8\. 下游任务损失：基于 prototype 的相似度分类

ProNoG 的下游任务包括：

1.  node classification；
    
2.  graph classification。
    

它采用类似 GraphPrompt 的 prototype-based loss。

对于任务 $t$，训练集为：

$$
D_t=\{(x_i,y_i)\}
$$

其中 $x_i$ 可以是节点，也可以是图。

对于每个类别 $c$，构造类别原型：

$$
\bar{h}_{t,c}
$$

它是所有属于类别 $c$ 的 labeled nodes/graphs 的平均 embedding。

然后对样本 $x_i$ 计算它和各类别 prototype 的相似度：

$$
L_{down}(\phi_t) = -\sum_{(x_i,y_i)\in D_t} \ln \frac{ \exp( \frac{1}{\tau} sim(\tilde{h}_{t,x_i},\bar{h}_{t,y_i}) ) }{ \sum_{c\in Y} \exp( \frac{1}{\tau} sim(\tilde{h}_{t,x_i},\bar{h}_{t,c}) ) }
$$

其中：

-   $\tilde{h}_{t,x_i}$：经过 prompt 调整后的节点/图表示；
    
-   $\bar{h}_{t,y_i}$：真实类别的 prototype；
    
-   $\tau$：temperature；
    
-   $sim(\cdot,\cdot)$：相似度函数。
    

这个损失的目标是：

> 让样本更接近自己类别的 prototype，远离其他类别的 prototype。

---

# 9\. 用于节点分类

对于 node classification：

1.  输入图 $G=(V,E)$；
    
2.  使用预训练 GNN 得到每个节点表示 $h_v$；
    
3.  对每个节点提取 2-hop 子图 $S_v$；
    
4.  用相似度加权 readout 得到 $s_v$；
    
5.  condition-net 生成 prompt：
    

$$
p_{t,v}=CondNet(s_v;\phi_t)
$$

6.  调整节点表示：
    

$$
\tilde{h}_{t,v}=p_{t,v}\odot h_v
$$

7.  用类别 prototype 进行分类。
    

训练时只更新：

$$
\phi_t
$$

也就是 condition-net 参数。

预训练 GNN 参数保持冻结。

---

# 10\. 用于图分类

对于 graph classification，需要先得到每个节点的 prompt-adjusted embedding：

$$
\tilde{h}_{t,u} = p_{t,u} \odot h_u
$$

然后对图中所有节点做 readout：

$$
\tilde{h}_{t,G} = \sum_{u\in V} \tilde{h}_{t,u}
$$

这样得到整张图的表示。

之后同样构造类别 prototype，并使用相似度 softmax loss 训练。

也就是说，图分类中，ProNoG 的图表示来自：

> 图中所有节点经过节点专属 prompt 调整后的表示之和。

# 11\. ProNoG 的完整算法流程

可以把 ProNoG 理解成下面的流程：

```
输入：  
\- 图 G=(V,E)  
\- 节点特征 X  
\- 下游 few-shot labeled set  
\- 预训练任务  
  
阶段一：非同配图预训练  
1\. 选择 non-homophily pre-training task，例如 GraphCL  
2\. 使用无标签图数据预训练图编码器  
3\. 得到预训练 GNN encoder  
  
阶段二：条件 prompt 学习  
1\. 冻结预训练 GNN encoder  
2\. 对每个节点 v，得到预训练表示 h\_v  
3\. 提取节点 v 的 δ-hop ego-network S\_v  
4\. 对 S\_v 做相似度加权 readout，得到 s\_v  
5\. 将 s\_v 输入 condition-net  
6\. 生成节点专属 prompt p\_{t,v}  
7\. 使用 p\_{t,v} 调整节点表示：  
   h̃\_{t,v}=p\_{t,v}⊙h\_v  
8\. 构造类别 prototype  
9\. 通过相似度分类损失优化 condition-net  
10\. 推理时，根据样本与类别 prototype 的相似度预测类别
```

---

# 12\. 和普通 graph prompt 方法的区别

| 方法 | Prompt 形式 | 是否节点自适应 | 是否考虑非同配模式 |
| --- | --- | --- | --- |
| GraphPrompt | 通常使用统一 prompt/prototype | 否 | 否 |
| GraphPrompt+ | 改进 prompt 表达 | 部分 | 不是专门针对非同配 |
| GPF / GPF-plus | 在节点特征上加 prompt | 部分 | 否 |
| ProNoG | condition-net 生成节点专属 prompt | 是 | 是 |

ProNoG 的关键区别是：

> prompt 不是全局共享的，而是由每个节点的局部多跳结构模式动态生成。

# 13\. 为什么 ProNoG 适合 few-shot？

few-shot 下，每类只有很少标签。如果直接训练 GNN，容易过拟合。

ProNoG 的 few-shot 友好性体现在：

1.  **冻结预训练 GNN**  
    不更新大模型参数，减少过拟合。
    
2.  **只训练轻量 condition-net**  
    可学习参数少，更适合低资源场景。
    
3.  **利用无标签图结构**  
    通过多跳 ego-network 提取局部结构模式。
    
4.  **每个节点自适应 prompt**  
    即使标签少，也能通过局部非同配模式调整表示。
    

论文实验中，ProNoG 在 one-shot node classification 和 one-shot graph classification 中大多数数据集都优于基线，尤其在 Wisconsin、ENZYMES 等数据集上提升明显。



---

# 14\. 消融实验说明了什么？

论文做了几个变体：

| 变体 | 含义 |
| --- | --- |
| NoPrompt | 不使用 prompt，只训练分类器 |
| SinglePrompt | 所有节点使用同一个 prompt |
| NodeCond | 不读取子图，直接用节点 embedding 生成 prompt |
| ProNoG\\sim | 子图 readout 不用相似度加权，只用 mean pooling |
| ProNoG | 完整方法 |

实验结果显示，完整 ProNoG 通常最好。说明几个组件都很重要：

1.  **prompt learning 有必要**，NoPrompt 不够；
    
2.  **节点专属 prompt 有必要**，SinglePrompt 不够；
    
3.  **局部子图模式有必要**，只用节点自身 embedding 不够；
    
4.  **相似度加权 readout 有必要**，简单 mean pooling 不够。


---

# 15\. 方法的本质理解

ProNoG 可以从三个层面理解。

### 第一层：预训练任务选择

它认为 link prediction 这类基于同配假设的任务，在非同配图上不稳。

所以它倾向于使用 GraphCL 这类不直接依赖连边同配性的预训练任务。

### 第二层：节点局部模式建模

它认为非同配不是图级统一属性，而是节点级差异属性。

所以每个节点都需要根据自己的局部结构生成不同 prompt。

### 第三层：轻量参数适配

它不微调整个 GNN，而是冻结 GNN，只训练 condition-net。

这样既保留预训练知识，又适合 few-shot。

---

# 16\. 一句话总结

ProNoG 的核心方法是：

> 先用不依赖同配假设的预训练任务学习图编码器，再通过读取每个节点的多跳 ego-network 捕获其局部非同配模式，并用 condition-net 为每个节点生成专属 prompt，最后在冻结预训练 GNN 的情况下，用少量标签完成节点分类或图分类适配。
