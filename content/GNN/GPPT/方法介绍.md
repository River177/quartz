它的方法核心可以概括成一句话：

**先用“边预测”把 GNN 预训练好，再把下游“节点分类”任务改写成和边预测同形的“token pair 连边判断”问题，这样就能直接复用预训练好的 GNN 和 projection head，而不是重新换一个分类头再慢慢 fine-tune。**

它要解决的根本问题是：传统 graph pre-train + fine-tune 里，**预训练目标和下游目标不一致**。例如预训练时做的是“两个节点有没有边”，但下游做的是“一个节点属于哪一类”。这时如果直接丢掉原来的 pretext head，换成新的分类头再微调，就会出现两个问题：一是要花很多 epoch 才能把模型从“pairwise edge prediction”拉到“single-node multi-class classification”；二是甚至会出现负迁移，性能不如不预训练。GPPT 的核心思想，就是不强迫模型去适应一个新头，而是**把下游任务改写得更像原来的预训练任务**。

这篇论文的方法分成三层看最清楚：  
**预训练层、prompt 设计层、prompt tuning 层。**

先说第一层，**预训练层**。  
作者选的是最简单、也最通用的 pretext：**masked edge prediction**。做法就是先随机 mask 掉一部分边，得到一个缺边图 $G^{pre}$，再用 GNN 在这个图上学节点表示 $h_i=f_\theta(G^{pre},v_i)$，然后用一个 projection head $p_\phi^{pre}$ 去判断节点对 $(v_i,v_j)$ 是否连接。训练目标是最小化节点对的边预测损失。也就是说，预训练后的模型本质上学到的是：**给你两个“对象”，我能输出它们有多像/有没有连接关系。** 这个 pairwise 形式，正是后面 prompt 改写时要利用的。



第二层是整篇论文最关键的部分：**graph prompting function**。  
作者先给出一个很 general 的定义：用一个 prompting function $f_{prompt}$ 把原来的单个节点 $v_i$ 变成一个 prompt $v_i'$。但这里不是像 NLP 那样加一句自然语言模板，而是把它变成一个**二元 token pair**：

$$
v_i' = [T_{task}(y), T_{str}(v_i)]
$$

其中：

-   $T_{task}(y)$：**task token**，表示“某个候选类别 $y$”
    
-   $T_{str}(v_i)$：**structure token**，表示“目标节点 $v_i$ 及其结构信息”
    
    
    

这一步其实就是论文最巧妙的地方。原来节点分类是在问：

“节点 $v_i$ 属于哪一类？”

现在它被改写成：

“候选类别 token $T_{task}(y_c)$ 和目标节点的 structure token $T_{str}(v_i)$ 之间，是不是应该连边？”

于是，下游的多分类问题就被改写成了多个二分类的 pairwise matching 问题，这和预训练时的边预测形式就对齐了。对于每个候选类别 $y_c$，都构造一个 token pair $[T_{task}(y_c),T_{str}(v_i)]$，再送入预训练好的 pairwise projection head，输出一个 linking probability。谁的分数最高，就把节点判成哪一类。

所以 GPPT 的整体推理过程可以写成很直白的三步：

1.  对一个待分类节点 $v_i$，枚举所有类别 $y_1,\dots,y_C$；
    
2.  对每个类别都构造一个 token pair $[T_{task}(y_c),T_{str}(v_i)]$；
    
3.  用预训练好的边预测头计算每个 pair 的连边概率，取最大者对应的类别作为预测结果。
    

论文把这个过程叫作三部分：**prompt addition、prompt answer、prompt tuning**。  
其中：

-   **prompt addition**：为一个节点和所有候选类别构造 token pairs；
    
-   **prompt answer**：把 token pair 映射成向量，输入预训练好的 projection head，得到连边分数，并取最大分数类别作为答案；
    
-   **prompt tuning**：仍然沿用 pretext 的 pairwise loss 来训练，使“正确类别 token 和该节点结构 token 应该连边，错误类别 token 不该连边”。
    

第三层是 **task token 和 structure token 怎么具体设计**。  
这也是方法能否有效的关键。

先看 **task token**。  
对于每个类别 $y_c$，作者不把它看成一个离散 label，而是把它嵌入成一个可学习向量：

$$
e_c = T_{task}(y_c)\in \mathbb{R}^d
$$

如果有 $C$ 个类别，就有一个 token 矩阵 $E=[e_1,\dots,e_C]^T$。直觉上，这个 token 就像“该类别的 prototype node”。分类时，相当于让目标节点去和所有类别 prototype 配对，看它最像哪个类。



但作者认为，一个全局共享的类别 token 不够，因为图通常有明显的 **cluster structure**。预训练做边预测后，节点 embedding 往往也按 cluster 聚在一起；此时同一类别在不同 cluster 里的最佳 prototype 位置可能不一样。所以论文又提出了 **cluster-based task token generation**：

-   先用图划分算法，比如 METIS，把图切成 $M$ 个不重叠 cluster；
    
-   然后对每个 cluster 单独学习一套 task token 矩阵
    

$$
E^m = [e^m_1,\dots,e^m_C]^T
$$

-   如果节点 $v_i$ 在第 $m$ 个 cluster，就用该 cluster 下对应类别的 token $e_c^m$。
    
    
    

这一步本质上是在做“**局部类别原型**”，而不是全局统一类别原型。作者认为这样更适合图数据本身的簇结构。实验里也验证了，去掉 clustering 后性能会下降。

再看 **structure token**。  
作者认为只拿目标节点自己做分类不够，因为在图里，邻居常常提供很强的提示信息。于是他们把 structure token 设计成目标节点和一阶邻居的注意力聚合表示：

$$
e_{v_i} = a_i h_i + \sum_{v_j\in N(v_i)} a_j h_j
$$

其中 $h_i$ 和 $h_j$ 是预训练 GNN 产生的节点表示，$a_i,a_j$ 是 attention 学出来的权重。也就是说，structure token 不是单个节点 embedding，而是一个**带邻域上下文的局部结构表示**。作者把它看作图里的 prompt 模板，类似 NLP 里自然语言模板给分类提供语义上下文，只不过这里的上下文来自邻域结构。



接着是 **prompt initialization 和 orthogonal constraint**。  
这是这篇论文里很实用的两个技巧。

先说初始化。作者认为 task token 的理想位置，应该接近对应类别节点表示的中心。如果你纯随机初始化 token，训练一开始就可能很乱，导致分类过程被错误引导。所以他们不是随机初始化 $e_c^m$，而是直接用“**该 cluster 中、该类别训练节点的预训练表示均值**”来初始化。这相当于先把每个类别 token 放到一个比较合理的位置上。



再说正交约束。  
如果不同类别的 token 太相似，那分类肯定容易混淆。所以作者额外加了一个正交正则：

$$
L_o = \sum_m \|E^m(E^m)^T - I\|_F^2
$$

它的作用就是让同一个 cluster 里的不同类别 token 尽量彼此正交、互不干扰。最终总损失就是：

$$
\min_{\theta,\phi,E_1,\dots,E_M} \sum_{(v_i,y_c)} L_{pre}(p_\phi^{pre}(e_c^m,e_{v_i});g(y_c,v_i)) + \lambda L_o
$$

并且参数初始化满足：

$$
\theta_{init}=\theta^{pre},\quad \phi_{init}=\phi^{pre}
$$

这说明 GPPT 不是重新搭一个下游分类器，而是**继续沿用预训练的 pairwise prediction 头**，只是在下游阶段再把 GNN、projection head 和 prompt token 一起轻微调优。

如果把 GPPT 的完整算法过程写成白话版，就是：

**第一步：预训练**  
在原图上做 masked edge prediction，得到预训练好的 GNN 参数 $\theta^{pre}$ 和 pairwise projection head 参数 $\phi^{pre}$。



**第二步：图划分**  
把图切成多个 cluster，为每个 cluster 准备单独的类别 task tokens。



**第三步：初始化 prompt**  
对每个 cluster、每个类别，用该类训练节点的预训练表示均值初始化对应的 task token。



**第四步：构造 structure token**  
对每个待分类节点，利用它和一阶邻居的预训练表示做注意力聚合，得到 structure token。



**第五步：构造所有候选 token pair**  
对节点 $v_i$，分别与每个候选类别 $y_c$ 组成 $[T_{task}(y_c),T_{str}(v_i)]$。



**第六步：计算 pair score 并回答**  
把每个 token pair 喂给预训练 projection head，得到连边概率；最大概率对应的类别就是预测类别。

**第七步：prompt tuning**  
用和预训练一致的 pairwise loss 继续训练，同时加上正交约束，使正确类别 token 和节点结构 token 更接近，错误类别更远。

这篇方法为什么有效，论文自己的逻辑大概有三点。

第一，**它桥接了 objective gap**。  
预训练本来就是 pairwise score learning，下游也被改成了 pairwise score learning，所以知识更容易直接迁移。

第二，**它复用了 pre-trained projection head**。  
传统 fine-tune 常常要扔掉原来的 pretext head，换一个新的分类头；GPPT 则保留原来的 pairwise head，不需要从头学习一个新的 decision interface，因此收敛更快。

第三，**它把图结构信息显式写进 prompt**。  
通过 structure token，分类时不只看目标节点本身，还看邻域；通过 cluster-specific task token，不同局部区域能有不同类别原型，适配图的 cluster 特性。

如果从局限性看，这篇 GPPT 其实也比较明确：

-   它主要针对的是 **node classification**；
    
-   它依赖的 pretext 是 **pairwise score 型任务**，文中主打的是 masked edge prediction；
    
-   它的 prompt 形式是 **token pair**，比后面那篇 “All in One” 的 prompt graph 更简单，也更特化。后者其实在论文里就明确说，GPPT 可以被看作它们更一般框架的一个特例。


一句话总结这篇 GPPT：

**它不是去改模型输出头来适应节点分类，而是把节点分类“伪装成”边预测，让预训练好的 GNN 直接回答“这个节点和哪个类别 token 最应该连边”，从而更高效地调用预训练知识。**
