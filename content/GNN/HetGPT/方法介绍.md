这篇 **HetGPT** 的方法，可以先抓一句总括：

**它不是重新 fine-tune 一个预训练好的异构图神经网络，而是在“冻结预训练 HGNN 与对比头”的前提下，额外学习一套 prompt，使下游的半监督节点分类被改写成“节点 token 与类别 token 的对比匹配”问题。** 这样既缩小了预训练目标和下游目标的差距，又减少了需要更新的参数量。



它主要想解决四个问题。第一，预训练常用对比学习，而下游是节点分类，二者目标不一致，容易负迁移。第二，标注节点很少时，普通 fine-tune 很容易过拟合。第三，预训练 HGNN 往往很大，全参数微调效率低。第四，现有 graph prompt 大多面向同构图，忽略了异构图里节点类型、元路径、不同邻域语义的复杂性。HetGPT 就是围绕这四点设计的。



整套方法可以分成五块看：

**1）prompting function 设计**  
**2）virtual class prompt**  
**3）heterogeneous feature prompt**  
**4）multi-view neighborhood aggregation**  
**5）prompt-based learning / inference**。论文图 1 基本就是这五部分的总流程。



先说整体流程。  
论文默认你已经有一个**经过对比学习预训练的 HGNN 编码器** $f_{\theta^*}$ 和对应的 **contrastive head** $g_{\psi^*}$。这两个模块先在异构图上做对比预训练，学会把正样本表示拉近、负样本表示推远。到了下游节点分类时，**这两个模块的参数全部冻结**，HetGPT 不再新增传统分类头，而是引入 prompt，让下游任务继续沿用预训练阶段的“对比匹配”范式。



---

### 1\. Prompting function：把节点分类改写成“节点—类别”的对比任务

论文认为，如果预训练是对比学习，那么下游任务最好也尽量写成对比形式。于是它设计了一个 prompting function：

$$
l(v)=[z_v,q_c]
$$

其中：

-   $z_v$：目标节点 $v$ 的 **node token**
    
-   $q_c$：类别 $c$ 的 **class token**。
    
    
    

这个式子很关键。它意味着：  
原来“把节点 $v$ 分到哪一类”这个分类问题，现在被改写成：

**“节点 token $z_v$ 和哪一个类别 token $q_c$ 最相似？”**

所以 HetGPT 的核心不是再接一个 softmax 分类器，而是把节点分类重新拉回到预训练时熟悉的“pairwise similarity / contrastive”范式里。


---

### 2\. Virtual class prompt：把每个类别变成一个可学习 token

这是 HetGPT 最重要的部分之一。  
论文没有直接把类别当离散 label 用，而是给每个类别都分配一个**可训练向量**，称为 **class token**：

$$
Q=\{q_1,q_2,\dots,q_C\}
$$

其中 $C$ 是类别数，每个 $q_c\in\mathbb R^d$，维度和预训练 HGNN 产生的节点表示一致。



这组 class tokens 组成了所谓的 **virtual class prompt**。直觉上，它不是死板的 one-hot 标签，而是一组能在嵌入空间里表达“某一类长什么样”的原型向量。  
这样做的好处是，在标注很少时，不必完全依赖少量节点直接训练分类边界，而是让模型去学习“类别原型”。这能缓解过拟合。



#### 初始化方式

论文不是随机初始化这些 class tokens，而是用**该类所有标注节点在预训练 HGNN 下的平均表示**来初始化：

$$
q_c=\frac{1}{N_c}\sum_{v\in V_L,y_v=c} h_v
$$

这里 $h_v$ 是预训练节点嵌入，$N_c$ 是第 $c$ 类标注节点数。  
这个初始化很合理，因为它让每个 class token 一开始就靠近本类节点的聚类中心，知识迁移会更平滑。



#### 正交正则

为了防止不同类别 token 靠得太近，论文还加了一个**正交约束**：

$$
L_{orth}=\|QQ^\top-I\|_F^2
$$

作用就是鼓励不同类别 token 保持区分性，让它们在嵌入空间里更分散。这样后面做相似度匹配时更稳定。



---

### 3\. Heterogeneous feature prompt：在输入特征空间里加“异构特征提示”

这是 HetGPT 和同构图 prompt 最大的不同之一。

很多同构图 prompt 方法只用一个统一 prompt 去改所有节点特征，但异构图里不同类型节点的特征语义和维度都可能不同。比如论文举的例子里，paper 节点可能是文本 embedding，author 节点可能是 one-hot。用同一个 prompt 去加所有类型，显然不太合理。



所以 HetGPT 引入了 **type-specific feature tokens**。  
对每种节点类型 $A$，不学习一个 prompt，而是学习一小组 basis vectors：

$$
F^A=\{f_1^A,f_2^A,\dots,f_K^A\}
$$

这里 $K$ 是超参数，表示该类型节点用多少个基础特征 token。这样总 prompt 参数量不依赖节点数，只和节点类型数、每类 token 数有关，比“每个节点一个 prompt”轻量得多。



对某个类型为 $A$ 的节点 $i$，它的原始特征 $x_i^A$ 会被加上这些 feature tokens 的加权和：

$$
\tilde x_i^A = x_i^A+\sum_{k=1}^K w_{i,k}^A f_k^A
$$

其中权重 $w_{i,k}^A$ 由 feature token 和节点原始特征的相似性经过 softmax 算出来。  
也就是说，节点不会平等地接收所有 prompt，而是根据自己原特征，自适应地组合出一个“适合自己”的 prompt。



然后，所有这种**被 prompt 过的特征**再送进**冻结的预训练 HGNN**，得到 prompted node embeddings。  
这一步的本质是：  
**不改预训练网络参数，只在输入特征空间里做一个针对下游任务的小幅改造。**  
这样既能让预训练表示朝下游任务适配，又保持参数高效。



---

### 4\. Multi-view neighborhood aggregation：面向异构图的节点 token 构造

如果直接把目标节点在预训练 HGNN 输出的表示当作 $z_v$，对于异构图往往不够。  
原因是异构图邻域很复杂：一个 target node 的邻居既可以来自不同**节点类型**，也可以通过不同**元路径**与它相关。论文认为仅仅看一跳邻居、或者只做普通平均，会忽略这种异构结构。



因此它设计了 **multi-view neighborhood aggregation**，从两个视角聚合邻域信息：

-   **type-based aggregation**
    
-   **metapath-based aggregation**。
    
    
    

#### 4.1 Type-based aggregation

首先按照网络 schema，看目标节点能直接连到哪些节点类型，比如 paper 可以连 author、subject、paper 等。  
对每一种邻居类型 $A_m$，先在该类型邻居集合上做一层 **node-level attention**，得到该类型对应的聚合表示 $h_i^{A_m}$。  
然后再在不同类型之间做一层 **semantic attention**，把这些类型级表示加权融合成一个 **type-based embedding**：

$$
z_i^{TP}
$$

这一步反映的是局部异构结构：  
**不同类型邻居对当前节点的重要性不同。**



#### 4.2 Metapath-based aggregation

第二个视角是元路径。  
同一个 target node 可能通过不同 metapath 获得不同的高阶语义，比如 PAP、PSP、APA、APCPA 等。论文对每条定义好的 metapath，都先聚合这条路径下的相关邻居，得到 $h_i^{P_n}$，再在多条 metapath 之间用 semantic attention 融合，得到一个 **metapath-based embedding**：

$$
z_i^{MP}
$$

这一步更强调全局/高阶语义，而不只是 schema 的局部一跳关系。



#### 4.3 合成最终 node token

最后，把 type-based embedding 和 metapath-based embedding 拼接，再过一个线性层和激活函数，得到最终的 **node token**：

$$
z_i=\sigma(W[z_i^{MP}\|z_i^{TP}] + b)
$$

这就是后面要和 class tokens 比较相似度的节点表示。



所以，HetGPT 里的 $z_v$ 不是单纯的节点 embedding，而是一个**融合了 prompt 后节点表示 + 类型视角 + 元路径视角**的综合 token。



---

### 5\. Prompt addition：把 node token 和 class token 拉到同一空间

因为 $z_v$ 和 $q_c$ 虽然维度一样，但分布未必完全可比，论文又加了一个很轻的 MLP，把二者都映射到统一的对比空间：

$$
z'_v=\text{MLP}(z_v),\quad q'_c=\text{MLP}(q_c)
$$

最后真正参与对比的是 $[z'_v,q'_c]$。  
这一步相当于做一个轻量投影头，保证 node token 和 class token 的相似度比较更稳定。



---

### 6\. Prompt tuning：仍然用预训练时的对比目标，而不是分类头

这一步最能体现 HetGPT 的思想。

对于一个有标签节点 $v$，传统 fine-tune 会接一个分类头，用 supervised CE loss。  
但 HetGPT 不这么做，它直接把该节点的**正样本**定义成“它所属类别的 class token”，负样本定义成“其他所有类别的 class tokens”：

$$
P_v=\{q_{y_v}\},\quad N_v=Q\setminus\{q_{y_v}\}
$$

然后继续沿用对比学习里的 **InfoNCE**：

$$
L_{con}= -\sum_{v\in V_L} \log \frac{\exp(\text{sim}(z'_v,q'_{y_v})/\tau)} {\sum_{c=1}^C \exp(\text{sim}(z'_v,q'_c)/\tau)}
$$

这其实已经非常像分类的 softmax 了，只不过语义上仍然是：

**让节点 token 更接近正确 class token，远离其他 class tokens。**



最终优化目标是：

$$
Q^*,F^*=\arg\min_{Q,F} L_{con}+\lambda L_{orth}
$$

这里注意，只优化：

-   virtual class prompt $Q$
    
-   heterogeneous feature prompt $F$
    

而**预训练 HGNN $f_{\theta^*}$** 和 **contrastive head $g_{\psi^*}$** 都不更新。



这也正是它“post-training prompting”这个名字的来源：  
它不是重新训练 backbone，而是在预训练模型外部加 prompt 并做轻量调节。



---

### 7\. 推理阶段怎么预测

推理时，对一个未标注目标节点 $v$，先按前面的步骤得到 $z'_v$，再和所有类别 token $q'_c$ 计算相似度，最后做 softmax：

$$
P(y_v=c)= \frac{\exp(\text{sim}(z'_v,q'_c))} {\sum_k \exp(\text{sim}(z'_v,q'_k))}
$$

取得分最高的类别作为预测结果。



所以你会发现，它的整个预测过程其实没有传统分类器，完全是：

**节点 token vs 类别 token 的相似度匹配。**



---

### 8\. 这篇论文的方法为什么成立

我觉得可以从三层理解。

第一层，**目标对齐**。  
预训练用对比学习，下游也改成对比式分类，因此比“预训练 + 新分类头 fine-tune”更一致，能缓解 objective gap。



第二层，**参数高效**。  
它不改 backbone，只学 class tokens 和 feature tokens，参数量很小。论文在实验里也专门强调 HetGPT 的 prompt tuning 收敛比 fine-tune 更快。图 4 里的 loss 曲线就体现了这一点。



第三层，**异构图适配更强**。  
现有同构图 prompt 方法没有处理异构图的 type/schema/metapath 多视角结构，而 HetGPT 明确把：

-   类别原型
    
-   类型特定 feature prompt
    
-   type-based 邻域聚合
    
-   metapath-based 邻域聚合
    

都整合进来了。



---

### 9\. 和前面几篇 graph prompt 论文的区别

如果和你前面看的 GPPT、GraphPrompt、PRODIGY 对比，HetGPT 的定位比较清楚：

-   **GPPT / GraphPrompt** 主要还是面向同构图
    
-   **PRODIGY** 做的是图上的 in-context learning
    
-   **HetGPT** 则是专门解决 **异构图上的 post-training prompt tuning**，重点是：  
    **冻结预训练 HGNN，用 prompt 去适配下游半监督节点分类。**

---

一句话总结这篇方法：

**HetGPT 把异构图上的节点分类改写成“节点 token 与类 token 的对比匹配”，通过 virtual class prompt 表示类别原型，通过 type-specific feature prompt 改造输入特征，再结合 type-view 和 metapath-view 的多视角邻域聚合得到节点 token，最后在冻结的预训练 HGNN 上只调 prompt，实现高效且更对齐的下游学习。**
