这篇 **GraphPrompter** 的核心思想，可以先概括成一句话：

**它不改 graph in-context learning 的基本范式，而是把“prompt 的整个生命周期”都优化一遍——先优化 prompt 怎么生成，再优化 prompt 怎么选，最后在测试时再动态补充 prompt，从而提升跨图、跨类别数场景下的泛化能力。** 论文把这三步分别叫作 **Prompt Generator、Prompt Selector、Prompt Augmenter**。

它针对的问题很明确。像 Prodigy、OFA 这类 graph in-context learning 方法，通常先从源图里随机采样子图/边作为 prompts，再随机选 few-shot 示例去辅导 query 预测。作者认为这里有两个主要短板：一是**随机生成的 prompt 子图里混有很多与任务无关的邻域噪声**；二是**随机选 prompt 不考虑 query 本身的特征**，所以常会选到不合适的示例。再加上当测试图的类别数明显大于预训练阶段时，模型的 in-context 能力会进一步下降。GraphPrompter 就是围绕这几个问题展开的。

从整体结构上看，它还是沿用了 prompt graph 这一类方法的基本框架。给定一个源图 $G=(V,E,R)$，先构造 **data graphs**：也就是每个输入样本 $x_i=(V_i,E_i,R_i)$ 的 $l$\-hop 邻域子图；再构造 **task graph**：把 prompt 样本和 query 样本都表示成 data nodes，再接上 label nodes，把下游任务统一成“预测 query data node 和 label node 之间的边标签，或者比较 query 与各 label 的相似度”。所以它不是重写任务形式，而是在这个既有 prompt-graph 框架上做 prompt 优化。

具体来说，方法分三层。

### 1\. Prompt Generator：先把 prompt 子图“生成得更干净”

第一步仍然是从源图中采样候选 prompt 节点和 query 节点。论文设候选 prompt 集为 $S$，query 集为 $Q$。对每个样本 $x_i$，先用随机游走/邻域采样拿到一个 $l$\-hop 子图：

$$
G_i^D=(V_i^D,E_i^D,R_i^D)\sim \oplus_{t=0}^{l}\text{Neighbor}(V_i,G,t)
$$

这一点和 Prodigy 类方法相似，先做局部上下文化。

真正的改进在于：GraphPrompter 不直接把这个采样出的子图拿去当 prompt，而是再做一个 **prompt graph reconstruction**。它的想法是：同一个局部子图里，并不是所有边、所有邻居都一样重要，很多边其实只是噪声。于是论文先对每条边 $(u,v)$ 算一个重构分数：

$$
z_{uv} = \text{MLP}_\phi(V_i(u),V_i(v),E_i(u,v))
$$

然后再通过 sigmoid 得到边权重：

$$
w_{uv}=\frac{1}{1+e^{-z_{uv}}}
$$

最后用一个 data-graph GNN 在加权后的子图上做聚合，得到子图表示 $G_i$。

这里可以把它理解成：  
**先随机采一个大致相关的邻域，再让一个可学习的重构层把其中更有用的拓扑边突出出来，把无关边压低。**

这一步的作用很像“拓扑去噪”。作者特别强调，这比直接用随机采样子图更好，因为原始邻域里混有 task-irrelevant 信息，会拖累 prompt 质量。

### 2\. Prompt Selector：再从候选 prompt 里选最合适的 few-shot 示例

第二层是整篇论文最关键的部分。作者认为，即使你已经有一堆还不错的候选 prompt 子图，如果给每个 query 还是随机抽 $k$ 个示例，效果依然会很差，因为这没有利用 query 自身的特征。

为此，Prompt Selector 做了两件事。

第一件事是加一个 **selection layer**，给每个候选 prompt 子图一个“重要性”分数：

$$
I_p = \sigma(\text{MLP}_\theta(G_p))
$$

然后用这个重要性去重加权 prompt 子图表示：

$$
G_p' = G_p \cdot I_p
$$

也就是说，模型在预训练时会学到“哪类 prompt 子图通常更值得被选”。

但作者也意识到，仅靠这个选择层不够。因为这个层是在预训练图上学到的，到测试时面对完全不同的下游图，分布变了，它可能不够泛化。所以第二件事是：在推理时再引入一个**无参数的 kNN 检索**。对于每个 query $q$，计算它和每个候选 prompt $p$ 的余弦相似度：

$$
\text{sim}(p,q)=\text{Cos}(G_p,G_q)
$$

然后把相似度和选择层分数结合起来，得到最终打分：

$$
\text{score}(p,q)=\text{sim}(p,q)+I_p\cdot I_q
$$

这个设计的意思是：

-   用 **kNN 相似度** 负责“这个 prompt 和当前 query 像不像”
    
-   用 **selection layer 分数** 负责“这个 prompt 本身质量高不高”
    

最后，论文不是简单对单个 query 选 top-k，而是对所有 queries 做一个 voting。每个 query 会给它 top-k 的 prompts 投票，票数由 $\text{score}(p,q)$ 决定，再把所有 query 的票加总，选票数最高的 $k$ 个 prompts，组成新的 prompt 集 $\hat S$。

这一层你可以理解成：

**Prompt Generator 解决“候选 prompt 本身要尽量干净”，Prompt Selector 解决“给当前 query 到底该用哪几个 prompt”。**

也就是说，它已经不是固定 prompt 了，而是**query-aware 的 prompt 选择**。

### 3\. Prompt Augmenter：测试时再在线补 prompt

第三层是 GraphPrompter 很有特点的一步。作者观察到，在测试图上，如果类别数很多，或者分布和预训练图差得比较大，仅靠固定的 few-shot candidate prompts 往往不够。这时候问题不只是“从已有 prompts 里选谁”，而是“原有 prompt 池本身不够覆盖新测试域”。

因此论文提出了一个 **online prompt augmentation**。思路很简单：在测试过程中，把一些模型最有把握的 query 样本及其预测标签（pseudo-label）也加入 prompt 池，用来帮助后续 query。为了避免 prompt 池无限膨胀，它设计了一个 cache $C$，大小为 $c$，只存储一部分在线样本。此时用于测试的 prompt 集变成：

$$
\hat S' = \hat S \cup C
$$

其中 $|\hat S'|=k+c$。

cache 更新用的是 **LFU（Least Frequently Used）** 策略。也就是：

-   对新 query，找出 cache 里与它最相似的条目
    
-   增加这些条目的使用频次
    
-   当 cache 满了，就优先替换掉最少使用的条目。
    

这一步本质上是一种 test-time adaptation，但它**不更新模型参数**，只是更新 prompt 池。作者认为这能利用目标域的测试时信息，帮助模型逐步适应新数据分布。

### 4\. 最终怎么预测

经过前面三步后，训练阶段用 selection layer 输出的重要性加权后的 prompt 集 $S_I$；测试阶段则用筛选后的 $\hat S$ 或增强后的 $\hat S'$。接着，把这些 prompts 和 query 一起送入 task graph：

$$
H = \text{GNN}_T(G^T(S_I \mid \hat S',Q))
$$

task graph 会把同类 prompt 的信息聚合成对应的 label embedding。最后，对某个 query，计算它和每个 label node 的余弦相似度，取最大者作为预测标签：

$$
y_q = \arg\max_{y\in Y}\text{Cos}(h_q,h_y)
$$

也就是说，最终预测阶段依旧继承了 Prodigy 这一类 prompt-graph in-context learner 的核心机制：**通过 task graph 把 prompt 示例转化成类别表示，再用 query 和类别表示做匹配。** GraphPrompter 改进的重点不是后端预测器，而是前面的 prompt 优化。

### 5\. 训练阶段到底学了什么

这篇论文的训练并不是重新发明一个全新的预训练框架，它沿用了 Prodigy 的两类预训练任务：

-   **Neighbor Matching**：让模型判断一个 query 属于哪个局部邻域
    
-   **Multi-Task**：构造 supervised few-shot prompt tasks 让模型学会通用任务适配。


对应的损失分别是：

$$
L_{NM} = \mathbb E_{q\in Q_{NM}} \text{CrossEntropy}(P_q^{NM}, y_q^{NM})
$$
 
$$
L_{MT} = \mathbb E_{q\in Q_{MT}} \text{CrossEntropy}(P_q^{MT}, y_q^{MT})
$$

总损失为：

$$
L = L_{NM} + L_{MT}
$$

训练时，Prompt Generator 里的 reconstruction module、Prompt Selector 里的 selection layers、以及后续 GNN 模块，都是在这个总损失下联合学习的。论文的 Algorithm 1 也明确说明：训练流程是“采样子图 → 重构边权 → 得到子图表示 → 计算 prompt importance → 构 task graph → 用总损失联合优化”。

所以，GraphPrompter 并不是只在测试时临时加个检索模块，而是：

**离线阶段学 prompt 质量，在线阶段再根据 query 动态检索和增强。**

### 6\. 这篇方法相对 Prodigy 的本质改进

如果把它和 Prodigy 对比，差异最核心的地方就在于：

Prodigy 做的是：

-   prompt graph 任务表示
    
-   in-context pretraining
    
-   测试时基本随机选 prompt。
    
    
    

GraphPrompter 做的是：

-   保留 prompt graph 和 in-context learner 主干
    
-   但把 **prompt construction / selection / augmentation** 全都做成可优化、可自适应的过程。
    

所以你可以把它理解成：

**它不是提出一个全新的 graph ICL backbone，而是给 Prodigy/OFA 这一类 prompt-graph 方法加了一套“prompt engineering + retrieval augmentation + online adaptation”的图版本。** 这一点和 LLM 里“选更好的 demonstrations、再做 test-time retrieval/augmentation”非常类似。

### 7\. 方法为什么有效

从论文自己的逻辑看，主要有三点。

第一，**重构层能减少子图噪声**。随机采样到的邻域未必最适合任务，reconstruction 会重新加权边，突出更有效的拓扑关系。

第二，**检索式 prompt selection 比随机选更贴合 query**。kNN 负责从语义相似度角度找近邻，selection layer 负责从预训练经验角度判断 prompt 质量，二者结合比单独使用任一种都更稳。论文消融里也指出，“w/o kNN” 和 “w/o SelectionLayers” 都明显差于完整模型。

第三，**online prompt augmentation 能提升跨数据集、跨类别数的泛化**。尤其当测试类别数很多时，固定 prompt 池不够，cache 中的 pseudo-labeled test samples 相当于给模型不断补充新的上下文。

### 8\. 一句话总结

这篇论文提出的方法，本质上是：

**在 graph in-context learning 的 prompt-graph框架上，引入一个三阶段的 prompt 优化系统：用 Prompt Generator 重构并去噪候选 prompt 子图，用 Prompt Selector 结合选择层与 kNN 做 query-aware 的 prompt 检索，再用 Prompt Augmenter 在测试时通过 LFU cache 动态补充高置信 pseudo-label prompts，从而提升跨图、跨类别数场景下的图 in-context learning 表现。**
