触发器（Trigger）是数据库中一种特殊的存储过程，它不需要用户手动调用，而是由数据库系统在特定的事件（如 `INSERT`、`UPDATE`、`DELETE`）发生时**自动触发执行**。

根据笔记 [[16-17]] 第 8 题的示例以及通用的 SQL 标准，详细讲解触发器的写法、结构和常见应用场景。

---

### 1. 触发器的基本语法结构

一个标准的触发器定义通常包含以下几个核心部分：

```sql
CREATE TRIGGER 触发器名称
{ BEFORE | AFTER }                             -- 1. 触发时机
{ INSERT | UPDATE | DELETE }                   -- 2. 触发事件
ON 表名                                        -- 3. 作用对象
FOR EACH ROW                                   -- 4. 触发频率（行级触发）
BEGIN
    -- 5. 触发器逻辑代码（SQL 语句）
    -- 可以使用 NEW.列名 和 OLD.列名 访问数据
END;
```

#### 详细解析：

1.  **触发时机 (`BEFORE` / `AFTER`)**：
    *   `BEFORE`：在数据真正修改**之前**执行。常用于数据校验、格式化或拒绝操作（如笔记中的例子）。
    *   `AFTER`：在数据修改**之后**执行。常用于记录日志、同步更新其他表。

2.  **触发事件 (`INSERT` / `UPDATE` / `DELETE`)**：
    *   指定哪种操作会激活触发器。

3.  **引用变量 (`NEW` / `OLD`)**：
    这是编写触发器逻辑最关键的部分：
    *   **`NEW.列名`**：代表**即将插入**或**更新后**的新数据。（仅用于 `INSERT` 和 `UPDATE`）
    *   **`OLD.列名`**：代表**更新前**或**被删除**的旧数据。（仅用于 `UPDATE` 和 `DELETE`）

### 2. 实战案例详解

为了让你更清楚，我将结合笔记中的场景和常见业务场景给出三个例子。

#### 案例 A：数据校验（笔记 [[16-17]] 第 8 题同款）
**需求**：在向 `住宿` 表插入记录前，如果 `退房日期` 为空，则禁止插入（回滚）。

```sql
CREATE TRIGGER check_checkout_date
BEFORE INSERT ON 住宿          -- 在插入之前触发
FOR EACH ROW
BEGIN
    -- 检查新插入数据的退房日期是否为空
    IF NEW.退房日期 IS NULL THEN
        -- 不同的数据库报错方式不同，这里演示通用的逻辑
        -- 在 MySQL 中通常使用 SIGNAL 抛出错误来中断操作
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '退房日期不能为空';
        
        -- 笔记中的写法是 ROLLBACK，这在某些特定环境（如旧版教材）常用
        -- 但在现代 MySQL 触发器中直接写 ROLLBACK 是非法的，通常通过报错来隐式回滚
    END IF;
END;
```

#### 案例 B：自动记录日志（审计功能）
**需求**：当 `客人` 表的电话号码被修改时，将旧号码和新号码记录到 `日志表` 中。

```sql
CREATE TRIGGER log_guest_update
AFTER UPDATE ON 客人           -- 在更新完成后触发
FOR EACH ROW
BEGIN
    -- 只有当电话号码发生变化时才记录
    IF OLD.电话 <> NEW.电话 THEN
        INSERT INTO 日志表 (客人ID, 修改时间, 旧电话, 新电话)
        VALUES (OLD.身份证号, NOW(), OLD.电话, NEW.电话);
    END IF;
END;
```

#### 案例 C：级联更新（数据同步）
**需求**：当 `房间` 表的 `房间号` 发生变更时（虽然主键很少变，但假设发生了），同步更新 `住宿` 表中的房间号。

```sql
CREATE TRIGGER sync_room_id
AFTER UPDATE ON 房间
FOR EACH ROW
BEGIN
    UPDATE 住宿
    SET 房间号 = NEW.房间号    -- 设置为新的房间号
    WHERE 房间号 = OLD.房间号; -- 找到所有原本属于旧房间号的记录
END;
```

### 3. 编写触发器的注意事项

1.  **避免死循环**：
    *   千万不要在 `A` 表的触发器里去更新 `A` 表本身，这会导致无限递归调用，最终报错。

2.  **性能影响**：
    *   触发器是同步执行的。如果你的 `INSERT` 操作非常频繁，而触发器里逻辑又很复杂（比如涉及大量计算或锁表），会严重拖慢写入速度。

3.  **事务性**：
    *   触发器和触发它的语句通常属于同一个事务。如果触发器执行失败（报错），那么原始的 SQL 语句（如 `INSERT`）也会回滚，不会生效。

4.  **`NEW` 和 `OLD` 的可用性总结**：

| 操作类型       | NEW (新值) | OLD (旧值) |     |
| :--------- | :------- | :------- | --- |
| **INSERT** | ✅ 可用     | ❌ 不可用    |     |
| **UPDATE** | ✅ 可用     | ✅ 可用     |     |
| **DELETE** | ❌ 不可用    | ✅ 可用     |     |

### 4. 针对考试/笔记的特别提示
在你的笔记 [[16-17]] 第 8 题中，参考答案使用了 `ROLLBACK`：
```sql
IF NEW.退房日期 IS NULL THEN
    ROLLBACK;
END IF;
```

**注意：** 在实际的 MySQL 环境中，触发器内部是不允许显式调用 `COMMIT` 或 `ROLLBACK` 语句的。但在**理论考试**或某些特定的数据库系统（如 SQL Server 的某些配置）中，这种写法用来表达“拒绝操作并回滚事务”的逻辑是完全正确的。如果是在上机实操，建议使用 `SIGNAL SQLSTATE` 报错的方式。a
